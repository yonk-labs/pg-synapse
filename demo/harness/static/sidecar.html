pg_synapse sidecar to a remote Postgres

← back to the main demo

The same agent kernel as the in-database extension, running as an out-of-process binary (pg-synapse-sidecar) beside a Postgres it cannot extend: managed cloud DBs like Amazon RDS, Cloud SQL, Neon, Supabase. It reaches the database over an ordinary connection (sqlx / libpq). This page talks to a live sidecar and proves it.

Topology

Kernel runs outside the database. SQL tools reach into the cloud DB over the wire; external tools and the LLM leave to the internet.

Live probe

The harness relays to the sidecar's v1 API server-side (no browser CORS). Every value below is reported by the remote database, through the sidecar.

Run an agent

A full tool-calling run, proxied to the sidecar's POST /v1/execute. The sidecar (a host process) makes the LLM call and drives the remote DB. Needs an agent + LLM profile registered on the sidecar (via its /v1/admin/* API).

Run it yourself

Two containers: a stock Postgres standing in for RDS, plus the sidecar.

docker compose -f docker-compose.sidecar.yml up --build
# rds:     stock postgres:17, synapse schema seeded by plain DDL (no extension)
# sidecar: pg-synapse-sidecar, connects over the wire, v1 HTTP API on :8088

Then set this page's URL to http://localhost:8088 and probe.
